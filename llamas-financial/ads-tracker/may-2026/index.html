WHY THIS PAGE
IS LEAN.

A full paid-performance report shows spend, impressions, clicks, CTR, CPC, conversions, CPL, and a search-terms breakdown per campaign. To pull those numbers, the report needs API access to the Google Ads account. Two standard routes both fail today. Here is each one and the path to fix.

Re-authorize Pipeboard MCP (fastest fix)

Pipeboard is the Markology standard route for pulling Google Ads + Meta Ads campaign data into reports. The MCP token expired and now returns "requires re-authorization (token expired)" on every call (verified today). Re-auth is a one-time browser flow from Whitney's MCP settings: open Pipeboard MCP, click reconnect, sign in. Five minutes. After re-auth, this tracker auto-pulls live campaign metrics on the next refresh.

Path A · 5 min
B

Octavio grants admin access to Llamas Google Ads

Markology's Google OAuth refresh token already covers the adwords scope (added 2026-05-19 per the OAuth scope expansion note), but the Llamas Google Ads account is not yet linked under a manager account Markology has access to. If Octavio grants admin or standard access on the Google Ads account to whitney@markology.io, the existing token works without any developer-token registration. This is the cleaner long-term solution.

Path B · client action
C

Complete Google Ads developer-token registration

Direct Google Ads API calls return 404 because the request needs a developer-token header on top of the OAuth access token. Google issues developer tokens through a one-time application at the Google Ads API Center (approval takes 1-3 business days for production tier, instant for test tier). Once issued, every Markology client account becomes directly queryable through the existing OAuth refresh token. Highest upfront effort, broadest long-term unlock.

Path C · 1-3 days
Recommendation: ship Path A this week (re-auth Pipeboard, restores standing reporting flow), schedule Path B at the next Octavio call as a one-line ask (grants Markology long-term access independent of Pipeboard), and queue Path C as the agency-wide infra upgrade for Q3.
Conversion Tracking

THE PIXEL IS NOT FIRING.

Independent of the campaign-data access gap, there is a known conversion-tracking break on the Llamas site. The Google Ads conversion pixel on /thank-you/ is not firing, which is why the account currently reports zero conversions across active spend. This means every paid campaign appears non-converting in the Google Ads dashboard, regardless of whether real discovery calls are being booked through paid traffic.

Why this matters before any campaign decisions: until this pixel is fixed, Markology and Octavio are flying blind on paid ROI. Any "this campaign isn't working, kill it" or "this campaign is working, scale it" decision based on Google Ads conversion data is wrong by default. The 29 Paid Search sessions in May likely produced real conversions; the dashboard is simply not recording them. Fix the pixel first, then re-evaluate spend after a 30-day clean window.
