ISSUE 1. REDIRECTS.

P1 · Critical Fix this first. Everything else is downstream.

What we found.

Curl test against the old domain (using GET, since the WAF returns 405 on HEAD and may have masked this in earlier checks):

All 13 equivalent pages on sas-acct.com return 200, so the destinations exist. This is purely a redirect-rule problem.

Why it broke.

The old domain is on GoDaddy basic domain forwarding (DNS: ns43/44.domaincontrol.com, terminating at an AWS ELB at 15.197.225.128 / 3.33.251.168). GoDaddy basic forwarding only rewrites the bare root. There is no path-preserving rule, so every inner URL hits the apex server, which returns 404 with no Location header.

The fix.

Either of two paths recovers all 27 URLs in a single deploy:

  1. Registrar path (fastest). In GoDaddy, change the domain forward to a path-aware 301. Some GoDaddy plans gate this; if the option is unavailable, use path 2.
  2. Host path (recommended). Point sas-cpas.com DNS at the sas-acct.com host (WP Engine / Apache + NitroPack) and add a server-level path-preserving 301. Both Apache and Nginx snippets are below; full ready-to-paste kit is in the fix kit file linked at the bottom.

Apache (.htaccess on sas-cpas.com host).

# Single rule: 301 every path from sas-cpas.com to the same path on sas-acct.com
RewriteEngine On
RewriteCond %{HTTP_HOST} ^(www\.)?sas-cpas\.com$ [NC]
RewriteRule ^(.*)$ https://sas-acct.com/$1 [R=301,L]

Nginx (server block on sas-cpas.com host).

server {
    listen 80;
    listen 443 ssl;
    server_name sas-cpas.com www.sas-cpas.com;
    return 301 https://sas-acct.com$request_uri;
}

Verification (after deploy).

# Should all show: 301 -> https://sas-acct.com/[same path] -> 200
curl -sIL https://sas-cpas.com/franchise-accountants/
curl -sIL https://sas-cpas.com/robs/
curl -sIL https://sas-cpas.com/2025/03/10/take-advantage-of-robs-for-business-funding/

Post-deploy follow-through.

  • Resubmit sas-cpas.com sitemap in the legacy GSC property so Google sees the new 301 signals on the next crawl rather than waiting weeks.
  • Use GSC URL Inspection to request reindexation of the 5 highest-value franchise/ROBS pages.
  • Expect non-brand keywords to begin recovering within 3-6 weeks of the redirect fix; full equity transfer takes 2-3 months.

ISSUE 3. MISSING SITELINKS.

P2 Cannot be forced. Earned through site signals.

Google generates sitelinks (the indented set of links under the main result) algorithmically. They appear when Google has high confidence in the site's structure, navigation, and authority. sas-acct.com isn't showing them yet for three combinable reasons:

  1. Domain age and authority. sas-acct.com only entered SEMrush's index in March 2026. To Google it is effectively a brand-new domain that has not yet inherited sas-cpas.com's authority signals (which the broken redirects are blocking).
  2. Internal linking depth. Sitelinks are surfaced from the pages Google judges most important on the site. Internal linking signals which pages matter; this audit found weak service-page interlinking (Issue 5 below).
  3. Mixed brand signals. While both sas-cpas.com and sas-acct.com return separate content footprints in Google's index, the brand identity is split. Once redirects consolidate everything to sas-acct.com, brand signals will concentrate.

What controls sitelinks recovery. Fix Issue 1, complete Issue 5, keep the sitemap clean (already submitted), and Google will typically render sitelinks within 4-12 weeks of the consolidation signal stabilizing. There is no "request sitelinks" button. The legacy GSC "demote sitelinks" tool was retired in 2016.

ISSUE 5. EEAT + INTERNAL LINKING.

P3 sprint Queue for July restart.

EEAT gaps to close.

  • Author bylines on all blog posts. Each post should link to an author bio page (Michael Sommers, or whichever team member). Audit the 41 indexed blog posts; add bylines where missing.
  • Person schema on author pages. Add Person JSON-LD with credentials, work history, LinkedIn, sameAs. Michael's CPA + franchise expertise is the trust signal.
  • Organization schema on homepage and About. Currently the homepage has Article schema (per the meta audit). It should also carry Organization schema with founder, address, sameAs, and a credential list. Article on the homepage is the wrong type and may compete with the franchise-vertical pages for the topical anchor.
  • 1,400+ Franchise Clients / 2,800+ Locations Served. These already lead the ad RSAs (per the May 26 campaign refresh). They should also be on the homepage hero, the about page, and tagged in schema as aggregateRating or knowsAbout signals.
  • Top Workplaces 2026 award. Add Award schema and a footer/about callout. Currently not surfaced on-site.
  • Case studies / portfolio brands. The brand promotes franchise expertise across 1,400 clients but has no public case studies. Even two named, owner-quoted studies would lift trust signals significantly.

Internal linking sprint (priority order).

Per the Markology cross-client rule: weight equity to homepage and service pages, anchor text uses exact service keywords.

  1. Homepage to vertical service pages. Audit homepage body for in-body anchors to the 9 vertical pages (Auto, Beauty & Wellness, Coffee Shops, Education, Fitness, Healthcare, Home Services, Restaurant, Retail, Senior Care). Anchors should be the exact service keyword.
  2. Vertical pages cross-link to franchise-accounting and franchise-financial-reporting. Every vertical page should carry at least one in-body link to /franchise-accounting/ with the anchor "franchise accounting" and one to /franchise-financial-reporting/.
  3. ROBS hub-and-spoke. /robs/ as the hub, with body links from every ROBS-adjacent blog post (count: ~6 posts including the 2025/03/10 piece). Anchor: "ROBS financing" or "ROBS compliance" depending on context.
  4. All blog posts to at least one service page. Current SAS blog rule (already in CLAUDE.md) requires 2+ internal links per post with at least one to a service page. Audit existing 41 posts for compliance; backfill where missing.
  5. Add a global secondary nav of service categories. Currently the main nav is shallow. A secondary "Industries" mega-menu (already exists as the /header-with-megamenu/ template but appears unused) would push vertical pages into deeper crawl prominence.
